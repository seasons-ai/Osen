# "Osen" interface mockup

To open: double-click `design/mockup/index.html`. No build, server or network is needed.

The mockup is the reference look that the app is checked against. Its data is made up. The window is 1100×700 or larger, dark theme only. Every screen opens as a file, and every state opens by an address of the form `<file>#<key>` or by clicking the "Mockup · states" strip at the top of the screen (Russian on the page: «Макет · состояния»). The first key in a screen's variant list is that screen's default variant.

The style is autumn Osen: dark-brown background, warm (`--leaf`) for what is in progress, cool (`--rain`) for what has settled, no shadows and no glow. The reference for the main states of the six screens is the same-named pages of `design/mockup-osen/`; this directory is the reference for intermediate states and the template editor, built on the shared tokens `design/mockup-osen/brand/tokens.css`. Structural differences between these screens and `design/mockup-osen/` are carried over by changes 83–93.

The mockup pages' visible text stays Russian. Quotes in «…» below are that Russian text; where the app's English catalog has the label, it is given in parentheses.

## Styling variables

All values live in `design/mockup-osen/brand/tokens.css` — the file shared by the `design/mockup/` mockup, the `design/mockup-osen/` mockup and the app; each variable has its purpose noted there. All other files, including the `design/mockup-osen/*.html` pages, write a value equal to a variable only through `var(--…)`; a number stays only for values with no variable (layout sizes, colors with alpha, inexact values, the light theme `tuman` in `design/mockup-osen/styleguide.html`). Glow is off: `--glow-*` and `--glow-alpha` are zero, `--tint-alpha` is `0%` (chips and badges without fill). `--p1`…`--p8` equal `--text-dim`: participants are told apart by number, and only the state gives color. The style rules are in `design/mockup-osen/SPEC.md`.

### Rules for applying

1. An element''s color is set through `--c` by the attributes `data-p="N"` (participant, `--p1`…`--p8`, all equal to `--text-dim`) and `data-tone="…"` (`accent`, `ok`, `warn`, `danger`, `info`, `muted`). The element takes its color from `var(--c)`; no colors of its own are introduced:

   ```css
   [data-p="1"]{--c:var(--p1)}
   [data-tone="ok"]{--c:var(--ok)}
   ```

   Status tone: something in progress (running, thinking, the indicator before agreement) — `accent`; something settled (agreement, «согласен» ("agreed"), «отвечен» ("answered"), the indicator at agreement) — `info`; `ok` — only technical checks, the «copied» and «lineup saved» notifications, and what is added in the version comparison (`design/mockup-osen/SPEC.md`, section 4).

2. No shadows or glow: `box-shadow` and `text-shadow` with glow are not used. The active state is conveyed by a border, a bar, a caption and an icon (`.participant--active`, `.btn--primary:hover`, `.card--interactive:hover`).

3. `--text-decor` is only for decorative marks (○, the «·» separator), not for text. On a `--bg-3` background (hover, selected row) secondary text is `--text-dim`, not `--text-faint`.

## Rules for checking the app against the mockup

- A state is never conveyed by color alone: always an icon and a caption.
- Text and caption contrast is at least 4.5:1; on `--bg-3` captions are `--text-dim`; no shadows or glow.
- With `prefers-reduced-motion: reduce`, animations and pulsing are off, and the state is visible statically.
- A 1100×700 window has no horizontal scrolling or overlaps.
- Participants are told apart by number; the avatar color is set only by the state (thinking, agreed, objecting).

### What `shell.js` does

- Icons: injects an SVG sprite into the page; an icon is inserted as `<svg class="icon"><use href="#i-…"></use></svg>`. List of ids: `i-plus`, `i-arrow-up`, `i-arrow-down`, `i-history`, `i-settings`, `i-check`, `i-x`, `i-alert`, `i-question`, `i-reply`, `i-stop`, `i-play`, `i-copy`, `i-download`, `i-chevron-right`, `i-chevron-left`, `i-chevron-down`, `i-user-off`, `i-terminal`, `i-cloud`, `i-key`, `i-edit`, `i-spark`, `i-clock`, `i-users`, `i-refresh`, `i-trash`, `i-doc`, `i-search`, `i-info`, `i-coins`, `i-loop`, `i-pin`.
- Rail: fills the `[data-rail]` element with the «М» mark and the items «Новое» ("New"), «История» ("History"), «Настройки» ("Settings"), «Образец» ("Sample"); the current item is taken from `data-nav` on `<body>` and gets `aria-current="page"`.
- Variants: reads `data-variants` on `<body>`, builds the `[data-mock-bar]` bar, shows the elements whose `data-variant` matches the `#key` in the address (the attribute may hold several space-separated keys) and hides the rest; reacts to a `#` change. If the key is not found, the first variant is shown.
- Tabs: inside `[data-tabs]`, a `[data-tab]` button shows the `[data-panel]` panel with the same value.
- Version comparison (`session.html` only): the switch in `.solution-tools` sets the `data-diff` attribute on `[data-tabs]`; elements with `data-view="diff"` are visible when it is `on`, `data-view="clean"` when `off`. On the v1 tab the switch is reset and locked; when the state is changed through the «Макет · состояния» bar, it returns to its initial position (on in `diff`).
- Stepper: the `[data-step]` buttons inside `.stepper` change `.stepper__value` within `data-min` and `data-max`.
