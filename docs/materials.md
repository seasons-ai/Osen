# Materials

`--attach <path>` attaches a file or folder to the discussion; the flag repeats. The engine reads the materials once before the start, their full text goes into the request of every turn; the participants have no tools and no disk access, the engine serves them the folder files they need from the snapshot on request. `--attach` of a folder saves a snapshot of the whole folder in `sessions/<id>/workspace/` before `session_created` (in the event `session.workspace = { files, chars }`), like the app; a folder larger than the limit is not rejected, a bounded initial set goes into the requests. Text snapshots are stored in `sessions/<id>/materials/`, and the journal holds only names, sizes and checksums.

```bash
COUNCIL_DEV=1 COUNCIL_HOME=.council-data npx council --topic "Что улучшить в формате шаблонов" --attach docs/templates.md --participant scripted:packages/core/scenarios/consensus/p1.json --participant scripted:packages/core/scenarios/consensus/p2.json --max-rounds 3
```

Before the start, ahead of the `Session …` line, a summary is printed: `Materials: <number>, size <characters> characters (limit <N>).`; if anything is skipped — `Skipped: <n>` and a line `  <name> — <reason>` for each. If the folder yielded at least one file, before them is printed `Folder snapshot: files <n>, size <characters> characters (bound 20000000).`; if anything did not make it into the initial set — `Not in the initial set: <n> (participants read on request)` and up to 20 lines `  <name> — <reason>` (then `  … and <k> more`). If links are given, `Link sources: <n>` is added and a line per link `  m2 ← https://example.com/docs/page.html · fetched <ISO time>`. The texts of the materials are not printed. An empty folder is not an error: `Materials: 0, size 0 characters …`, the discussion goes on without materials. The example above makes no model calls.

A link in the app: in the "Materials" block, the "Link" field and the "Add link" button accept an address with the same restrictions as `--url` (only public `http`/`https`, the core's limits). The main process downloads it, the window receives only the list view (name, size, source without a query); while a link is loading, "Materials preview" and "Start" are unavailable. The preview and the start work on one set without re-downloading, "Run again" carries the link over from the snapshot and `sources.json` without the network. The MCP server does not accept links yet. Check without the network and without cost: `COUNCIL_DEV=1 COUNCIL_HOME=<new folder inside the project> node apps/desktop/scenarios/url-materials/check.ts` (`--seed-only` prepares the folder and the stand for the window).

A check of the folder snapshot by the real `council` process on a generated large folder inside `.council-data`; no models are called:

```bash
COUNCIL_DEV=1 node packages/core/scenarios/folder/check-cli.ts
```

- In a folder, hidden names, names from `defaults.materialsIgnore` in `config.json` (initially `node_modules`, `dist`, `build`), symbolic links and files of other formats are skipped, the reason is given in the summary; for a file of another format it names its kind (see "Formats and reasons" below).
- Text encoding: detected by content, not by extension, in this order: PDF, documents and images as described here, then a UTF-16 BOM (LE `FF FE`, BE `FE FF`) decodes the file as UTF-16, then a NUL byte in the first 8192 bytes makes the file not text, then strict UTF-8 is accepted as is, then Windows-1251. A UTF-8 BOM is accepted and stripped, a UTF-16 BOM too. Windows-1251 is accepted when no control bytes (`00`–`08`, `0E`–`1F`, `7F`) are present, at least 90 % of the non-neutral bytes `0x80` and above are Cyrillic letters (Russian, Ukrainian, Belarusian) and at least 50 % of those are lowercase; neutral typographic bytes (guillemets, dashes, ellipsis, `№`, no-break space and the like) are counted in neither part. Text set entirely in capitals is not recognized, and KOI8-R is not recognized either. UTF-16 without a BOM is not text (the kind table below applies). UTF-32, broken UTF-16 (odd length, lone surrogate), a UTF-8 BOM followed by invalid UTF-8 and a file that fails the Windows-1251 test get the reason «encoding not recognized — UTF-8, UTF-16 with BOM or Windows-1251 is required» (an explicitly named file rejects the start, the same file in a folder is skipped). The encoding name is shown nowhere and the original bytes are not stored: the material, its `chars` and `sha256`, the preview, the snapshot and the turn requests carry the decoded UTF-8 text without a BOM. Links (`--url`) stay UTF-8 only.
- `.gitignore` rules: `.gitignore` files inside the attached folder (the root one and nested ones; a nested one acts on its own subtree) are applied as in git, including the `!` negation. Paths they exclude go neither into the initial set, nor into the folder snapshot, nor into the "Owner's folder" listing, and are printed in the summary as a separate section `Excluded by rules: <n>` — a line `  <name> — excluded by .gitignore rule: <rule>` each, a whole folder on one line (`proj/out/`), its contents are not traversed. This way build artifacts (`out/`, `release/`) do not eat the limit and the snapshot bound. Rules above the attached folder, global git settings and `.git/info/exclude` are not read; in a folder without `.gitignore` the behavior is as before; names from `defaults.materialsIgnore` keep the reason "in the ignore list". A file named explicitly in `--attach` is never excluded by rules. An unreadable `.gitignore` (no permissions, a symbolic link, larger than 1 MiB) does not reject the collection: its rules are not applied, in "Skipped" it has the reason "could not read — <reason>". The case of names in rules is not distinguished (as in git on macOS by default); the match with `git check-ignore` is checked by a core property test on generated trees.
- Folders of the same name: if several folders with one name are attached (case-insensitive and regardless of Unicode normalization form), the first keeps the name, the following get the suffix " (2)", " (3)", … — the smallest number not taken by the name of another attached folder or an already issued name (`/a/proj`, `/b/proj`, `/c/proj (2)` → `proj`, `proj (3)`, `proj (2)`). The name is common to the materials, the "Excluded by rules" section, the folder snapshot and the "Owner's materials".
- Bringing back what was excluded: `--include <path>` (repeats) brings an excluded file or folder back into the set — a folder whole, the rules inside it are not applied. The path is given as a file system path inside the attached folder or as a name from the "Excluded by rules" section (`--include proj/out/`); a name with a suffix (`--include "proj (2)/out/"`) brings back a path inside exactly that folder; a name without a suffix that fits several folders of the same name gives code 2 with a request to name the absolute path. When a file from an excluded folder is brought back, the rest of its contents stays in the section. A path the rules did not exclude rejects the start (code 2, `Materials not accepted:`). `--no-ignore` turns the rules off entirely and is incompatible with `--include` (code 2). Both flags work in `--preview-materials`; a start by `--prepared-materials <id>` uses the shown set and does not accept these flags.
- What is excluded by rules in the app: "Session setup" shows it as the section "Excluded by rules: N" with the buttons "Return" and "Exclude again" (the bridge actions `returnIgnored(id)` and `excludeIgnored(id)`); a return belongs to the current setup, is reset by "Clear" and is not carried over to a session repeat. Check without a window: `apps/desktop/scenarios/folder-ignore/check.ts` (the command is in `AGENTS.md`).

A check of the rules by the real `council` process on a fixture folder inside the project; no models are called:

```bash
COUNCIL_DEV=1 node packages/core/scenarios/ignore-rules/check-cli.ts
```

- The start is rejected (code 2, the message `Materials not accepted:` and the reasons line by line) if a path is not found or not readable, an explicitly named file is of an unsupported format (the reason names its kind, see "Formats and reasons") or is a symbolic link, or an explicitly named document is unfit, or an `.env` or `.env.*` file is named explicitly. The session is not created, the participants are not called.
- PDF: a file whose content starts with `%PDF-` (the extension does not matter for acceptance) is taken from the text layer, and pages without a text layer are recognized (change 214, below); the text is extracted locally before the start by the engine's common collector, the same for `--attach`, MCP `attachments` and the app ("Attach files", "Attach a folder", drag and drop). The material name is the file name; `chars`, `sha256`, the preview, the session snapshot (`sessions/<id>/materials/mN.txt`), the folder snapshot (`workspace/`) and the turn requests carry the extracted text, the PDF bytes are not stored in the session and journal, the file is not re-read after the start. Pages go in order separated by a blank line; the order of blocks within a page is as in the PDF file and may differ from the visual one. Per-file limits: 100 MiB of size (before reading), 2000 pages, 30 seconds, 512 MiB of extractor memory, 20000000 characters of text; exceeding one is a refusal with a reason, nothing is truncated, the regular materials limit and the folder snapshot bound apply on top of this to the extracted text. Reasons: «PDF is larger than 100 MiB», «PDF has more than 2000 pages», «PDF text extraction took longer than 30 seconds», «PDF text extraction used more than 512 MiB of memory», «PDF text is longer than 20000000 characters», «PDF is encrypted — no password is requested», «PDF is damaged», «PDF has no text» (no text on any page, also after recognition), «PDF has more than 200 pages without a text layer», «PDF text recognition took longer than 5 seconds per page», «PDF text recognition took longer than 300 seconds», «PDF text recognition used more than 512 MiB of memory», «text recognition is unavailable — the osen-ocr helper is missing» and «text recognition is unavailable — could not start the osen-ocr helper» (as for images), «could not recognize the PDF text — <code>», «could not extract PDF text — <code>». Recognition (change 214): a page whose PDF.js text is empty is rendered by the same helper `osen-ocr` in mode `pdf` (PDFKit, 2x scale, the long side capped at 4096 px) and recognized by Vision as an image; the choice is per page, so in a mixed document the text-layer pages stay exactly as PDF.js gave them and only the blank ones are recognized; the order and the blank-line separator are unchanged. Limits: 200 pages without a text layer (checked before the helper starts), 5 seconds per page, 300 seconds per file; exceeding one is a refusal, no partial text is kept. An explicitly named unfit PDF rejects the start (terminal: code 2, "Materials not accepted:"; MCP: a tool error; app: an error line in the "Materials" block, the already attached list is kept); the same PDF inside an attached folder is skipped with this reason, the rest is collected. In a folder larger than the limit, `.pdf` counts as a description when choosing the initial set. Not done: recognition of images inside pages that have a text layer, a password prompt (a PDF with a password is rejected; a PDF that opens without a password, for example only with a print restriction, is read), images, links (a link or script inside a PDF is not opened and not executed); CJK documents on predefined CMap tables can yield empty text (the CMap tables are not shipped, the same in all three entry points). The engine reads the file itself (rules as for text ones: no symbolic links, `.env` / `.env.*` are not opened) and passes the bytes to a separate extractor process with an empty environment (no keys) and the network disabled; it does not receive paths. The collector waits for it synchronously: while the extraction runs, the process (the app window, the MCP server) does not respond — usually a fraction of a second, in the worst case 30 seconds plus, for a scan, 300 seconds per file; the result is remembered in the process memory for an unchanged file (device, inode, size, modification time; launch failures, time limits and memory limits are not remembered), a repeated collection of the same attachments in the app does not extract again. Dependency: `pdfjs-dist` 6.4.299 (Mozilla PDF.js, Apache-2.0), the version is pinned in `packages/core/package.json`. Check without cost: `COUNCIL_DEV=1 COUNCIL_HOME=<new temporary folder inside the project> node packages/core/scenarios/pdf/check.ts` (real `council` and MCP over stdio, real app main modules, scripted participants, 0 model calls; scans go through the real `osen-ocr` after `npm run build:ocr`, helper stubs via `COUNCIL_OCR_HELPER`).
- Documents: the format is detected by content, not by extension: a ZIP signature and the main part type from `[Content_Types].xml` (DOCX and DOCM, XLSX and XLSM, PPTX and PPTM) or the `mimetype` entry in any position (OpenDocument ODT, ODS, ODP and their templates, EPUB; templates XLTX and POTX, shows PPSX, XLSB and the old XLS and PPT are not read and get their kind reason; a macro is never run, an explicitly attached ZIP that is not a supported document (including a truncated ZIP without its central directory, since nothing proves it is a document) is expanded as an archive, see "ZIP archives" below, while a package with `[Content_Types].xml` whose parts are broken, encrypted or declare a DTD is a damaged or encrypted document). The DOCX text has the body in file order (not the visual one: floating boxes and columns may differ), a table row per line with cells separated by a tab, footnotes and endnotes after a blank line, inserted revisions (deleted ones are dropped), one variant of `mc:AlternateContent`, text boxes once (as lines right after the paragraph that holds them). Not taken: headers and footers, comments, images, embedded objects; no password is requested. The XLSX text has the sheets in workbook order, hidden ones included, each starting with a line `# <sheet name>`, sheets separated by a blank line; a sheet row with at least one non-empty cell is a line, cells separated by tabs by column position, empty cells on the right dropped, empty rows skipped; a tab or newline inside a cell becomes a space; shared and inline strings as is, numbers as stored without the number format (dates stay serial numbers), booleans `TRUE` and `FALSE`, a formula gives only its saved value (never computed; no saved value — an empty cell), an error cell gives its code; chart sheets, charts, images, comments and merged-cell expansion are not taken. The PPTX text has the slides in presentation order (`p:sldIdLst`), hidden ones included, each starting with `# <N>`, slides separated by a blank line; shape text in tree order, a table row per line with cells separated by tabs, speaker notes (body placeholder only) after a blank line; footer, date and slide number are not taken; a slide without text still gives `# <N>`. OpenDocument text (ODT, ODS, ODP and templates): paragraphs, tables with cells separated by a tab, footnotes after a blank line, sheets as `# <name>` and pages as `# <N>` separated by blank lines, speaker notes after the page text, empty rows and trailing empty cells dropped; comments, deleted tracked changes, headers and footers, metadata and images are not taken. EPUB: chapters in the OPF spine order (including `linear="no"`) through the same HTML text rules as URL materials (text hidden by external CSS is included, as for URLs), joined by a blank line; images, styles, scripts and links are not loaded or run. Font obfuscation in `encryption.xml` does not block a book. Reasons: «format is not supported — OpenDocument drawing» (other kinds are named), «book is protected by DRM — its content is not available», «document is damaged — <part>». The engine passes the bytes over stdin to a separate extractor process with an empty environment and the network closed; it gets no paths; XML is read without DTD and entities. Per-file limits: 100 MiB of size, 30 seconds, 512 MiB of memory, 20000000 characters, 1000000 non-empty spreadsheet cells, 10000 ZIP parts, 512 MiB unpacked, compression ratio 200; exceeding one is a refusal, nothing is truncated. Reasons: «document is larger than 100 MiB» (a file with a ZIP signature over 100 MiB, document or archive, gets «ZIP is larger than 100 MiB — not expanded» instead), «document text extraction took longer than 30 seconds», «document text extraction used more than 512 MiB of memory», «document text is longer than 20000000 characters», «document has more than 10000 parts», «spreadsheet has more than 1000000 cells» (ru «в таблице больше 1000000 ячеек»), «document unpacks to more than 512 MiB», «a document part is compressed more than 200 times», «document is encrypted — no password is requested», «document is damaged», «document has no text» (also an empty workbook and a presentation without text), «could not extract document text — <code>». An explicitly named unfit document rejects the start; the same file inside an attached folder is skipped with the reason. In a folder larger than the limit, `.docx`, `.docm`, `.pptx`, `.pptm`, `.odt`, `.odp`, `.epub`, `.rtf` and `.doc` count as descriptions (`.xlsx` and `.ods` do not). RTF (the content starts with `{\rtf`, a UTF-8 BOM before it is allowed) and Word 97–2003 `.doc` (a Compound File Binary file with a `WordDocument` stream) are detected by content too and converted by `/usr/bin/textutil` running under `/usr/bin/sandbox-exec` with a fixed profile (no network, no file writes), an empty environment and the bytes on stdin; the same per-file limits apply (`DOC_LIMITS`), and a `.rtf` file without `{\rtf` stays plain text. An encrypted Office file (a Compound File Binary file with an `EncryptedPackage` stream, any extension) is refused with the reason «document is encrypted — no password is requested» (skipped inside a folder); Excel 97 and PowerPoint 97 files get the reasons «Excel 97 spreadsheet — save it as XLSX» and «PowerPoint 97 presentation — save it as PPTX», other Compound File Binary files (MSG and the like) «binary file of an unknown format» (see "Formats and reasons"); a damaged one is «document is damaged». If `sandbox-exec` or `textutil` is missing, the reason is «text could not be extracted — the system utility textutil is unavailable» and `textutil` is never run without the sandbox. In the app the extractor ships as `out/main/doc-extract.mjs` outside `app.asar`. Not done: text recognition, a password prompt, images.
- ZIP archives (change 215): an explicitly attached file with a ZIP signature that is not a supported document (the document formats above are checked first, by content; the extension does not matter: a `.docx` renamed `.zip` is a document, an archive renamed `.docx` is an archive) is taken as an attached folder. It is expanded in memory by the same extractor process as documents (empty environment, network closed, no paths); nothing is written to disk. Material names are `<archive file name>/<path inside>` (`proj.zip/src/a.ts`); a folder and archives of the same name are told apart like folders: `proj/`, `proj.zip/`, `proj.zip (2)/`. The folder rules apply to the entries: hidden names, `defaults.materialsIgnore`, `.gitignore` files inside the archive (root and nested; rules outside the archive are not read; what an archive's rule excludes cannot be brought back with `--include`), `.env` and `.env.*` are never extracted, symbolic links are skipped; the macOS service folder `__MACOSX/` and repeated names (the first entry is kept) are skipped with a reason. Every entry is read by the same readers as a file (text, PDF, documents, images; at most 50 images per archive), an unfit entry is skipped with its reason. The archive then works as a folder: the initial set, the folder snapshot (`workspace/proj.zip/…`), the "Owner folder" listing and reading on request; the archive is not read after the start. Skipped with a reason: «unsafe name in the archive» (`..`, an absolute path, a drive letter, NUL, a backslash; nothing is ever written outside `workspace/<prefix>/`), «nested archive is not expanded», «document is encrypted — no password is requested» (an encrypted entry), «archive entry is larger than 100 MiB». The whole archive is refused (an explicit one rejects the start, code 2): «ZIP is larger than 100 MiB — not expanded» (checked before reading; the same reason skips such a file inside a folder), «archive has more than 10000 entries», «archive unpacks to more than 512 MiB», «an archive entry is compressed more than 200 times» (all checked before unpacking), «expanding the archive took longer than 300 seconds» (listing and reading all entries), «archive is damaged», «archive is empty», «the archive has no usable file — N entries skipped» followed by the skips. An archive inside an attached folder is not expanded: «an archive inside a folder is not expanded — attach it separately». Not done: passwords, nested archives, tar, 7z, rar, gz, self-extracting and multi-volume archives, ZIP64, entry names not in UTF-8 (such an archive is damaged), links (`--url`) to archives.
- Images (change 213): PNG, JPEG, HEIC/HEIF, TIFF, GIF (first frame), BMP and WebP are detected by content signature, not by extension. The text is recognized offline by macOS Vision (accurate level, Russian and English, language correction) in the helper `osen-ocr` (Swift source `packages/core/src/ocr/osen-ocr.swift`, built by `npm run build:ocr` with `swiftc -O` into `packages/core/src/ocr/bin/`, not committed; `postinstall` builds it and only warns without Swift or macOS; `npm run dist` runs `build:ocr` first and fails without it). Lines are ordered top to bottom, left to right within a line (joined with a space), lines are joined with a newline. Only the recognized text reaches the models and the session (`chars`, `sha256`, the preview, the snapshot, the turn requests); the image bytes never do. The engine passes the bytes over stdin to a separate process, which answers with one JSON line on stdout; it gets no file paths, an empty environment and `/` as the working directory, and runs under `/usr/bin/sandbox-exec -p '(version 1)(allow default)(deny network*)(deny file-write*)'` (no write folder was needed, verified on macOS 26.6.2, 2026-10-22). Per-file limits: 50 MiB of size (checked by `fstat` before reading), 100 megapixels (from the header, before recognition), 30 seconds, 512 MiB of memory (supervised inside the helper; the parent kills the process after 32 seconds), 20000000 characters of text; exceeding one is a refusal with a reason, nothing is truncated. At most 50 images are recognized per attached folder, in the folder's name order; further images are skipped with a reason; explicitly attached files are not limited. An explicitly named unusable image rejects the start; the same image inside a folder is skipped with the same reason. Images are not descriptions when choosing the initial set of a folder larger than the limit. Reasons: «text recognition is unavailable — the osen-ocr helper is missing» (ru: «распознавание текста недоступно — нет помощника osen-ocr»), «text recognition is unavailable — could not start the osen-ocr helper» («распознавание текста недоступно — не удалось запустить помощника osen-ocr»), «no text found in the image» («на изображении не найден текст»), «the image is damaged» («изображение повреждено»), «the image is larger than 50 MiB» («изображение больше 50 МиБ»), «the image is larger than 100 megapixels» («изображение больше 100 мегапикселей»), «text recognition took longer than 30 seconds» («распознавание текста дольше 30 секунд»), «text recognition used more than 512 MiB of memory» («распознавание текста заняло больше 512 МиБ памяти»), «the image text is longer than 20000000 characters» («текст изображения больше 20000000 знаков»), «could not recognize the image text — <code>» («не удалось распознать текст изображения — <код>»), «the folder has more than 50 images — the first 50 were recognized» («в папке больше 50 изображений — распознаны первые 50»). Quality: this is recognition and it makes mistakes; photos, handwriting, small print and vertical text are weak, so check what the models were given in the preview. Not done: images inside documents and PDF, languages other than Russian and English, describing pictures without text, sending images to models, cloud recognition. Dev and test seam: `setOcrRuntime({ helper })` in one process, or `COUNCIL_OCR_HELPER=<absolute path>` only with `COUNCIL_DEV=1` (ignored otherwise); the helper is looked up in the order `setOcrRuntime`, `COUNCIL_OCR_HELPER`, `bin/osen-ocr`. In the app the helper ships as `Resources/ocr/osen-ocr` (see [deploy.md, "Checking the image"](deploy.md#checking-the-image)).
- Links: `--url <address>` (repeats, combines with `--attach`) adds the text of a public web page or document as a material; a link is taken only from this flag, addresses inside the topic or attached materials are not downloaded. Only `http` and `https` are accepted, an address with a login or password is rejected; both checks run before any network activity. Every hop (the given address and every redirect) is checked anew: the name is resolved once, all received addresses must be public (the list of non-public IPv4 and IPv6 ranges is `NON_PUBLIC_RANGES` in `packages/core/src/url/address.ts`, checked with `net.BlockList`, IPv4 forms inside IPv6 are rejected whole), the connection goes exactly to the checked address (Host and SNI stay from the link), so a DNS change after the check will not redirect the connection; at least one non-public address is a refusal before connecting. The request is `node:http`/`node:https`, method GET, `Accept: text/html, text/plain, text/markdown`, `Accept-Encoding: identity`, `User-Agent: model-council`; no cookies, authorization or provider keys, page resources (images, styles, scripts, frames) are not loaded. Per-link limits: one deadline of 15 seconds for name resolution, redirects, the response and text extraction together; no more than 3 redirects (301, 302, 303, 307, 308); no more than 2 MiB of body, including without `Content-Length`; only status 200 is accepted, a compressed response (`Content-Encoding` not `identity`) is rejected; nothing is truncated. `text/plain`, `text/markdown`, `text/html` are accepted, HTML only in UTF-8 (another `charset`, invalid UTF-8 and binary data are a refusal); plain text and markdown are taken as is. HTML is parsed by `parse5` inside a worker thread (`node:worker_threads`, 256 MiB heap, the network is closed in the thread, the thread is terminated at the deadline): the text is taken without `head`, `script`, `style`, `noscript`, `template`, `svg`, `iframe` and without elements with `hidden`, `aria-hidden="true"` or inline `display:none` / `visibility:hidden`; block elements become paragraphs separated by a blank line, `br` a line break, `pre` is kept as is, table cells are separated by a space. Not executed: JavaScript, external and `<style>` CSS (an element hidden by a stylesheet stays in the text), image `alt`, link addresses on the page, text recognition, PDF over the network, sites with a login; a page whose text appears only after JavaScript gives "no extractable text" and is rejected. A link material is an explicitly attached one: it goes after the local materials in `--url` order, goes in whole and is counted in the same `materialsChars` limit together with the explicitly attached files (over the limit — a refusal, no truncation), the folder files are chosen into the remainder of the limit. The name is built from the host and path without the `/` sign: `https://example.com/docs/page.html?x=1` gives `example.com_docs_page.html`, repeats get ` (2)`, ` (3)`. The text is stored as a regular snapshot `sessions/<id>/materials/mN.txt`, the `session_created` event still carries only `id`, `name`, `chars`, `sha256`; turns and `council resume` read only the snapshot, the network is not used after the start. The origin is written by the `sources.json` file (`{ "version": 1, "sources": [{ "id": "m2", "scheme": "https", "host": "example.com", "pathname": "/docs/page.html", "fetchedAt": "<ISO UTC>" }] }`): once next to `set.json` in `prepared-materials/<id>/` and in `sessions/<id>/materials/`, only if there is at least one link material; it describes the address given by the owner (redirects are not recorded). The query string, fragment and address credentials are not saved, not printed and do not get into logs — only the scheme, host and path; the path itself is saved, so a secret in a path will remain in the file: do not attach such links. A damaged `sources.json` of a prepared set makes the set `corrupt` (a refusal); an unreadable session `sources.json` does not block `council resume` (the text integrity is held by the snapshot `sha256`), the command prints `Link sources: could not read sources.json`. Old sessions and sets without the file are read as before. A refusal of any link is a start with code 2 and the message `Materials not accepted:` and a line `  «https://example.com/docs/page.html»: <reason>` per link (all given links are tried and all reasons are printed), the session is not created, the participants are not called. Reasons: «only http and https are supported», «an address with a login or password is not accepted», «could not parse the address», «name not found», «address <ip> is not public — download is forbidden», «redirect to a non-public address <ip> — download is forbidden», «more than 3 redirects», «redirect without a valid address», «HTTP response <code>», «compressed response (Content-Encoding: <value>) is not accepted», «format <type> is not supported — text/plain, text/markdown or text/html is required», «body is larger than 2097152 bytes», «did not finish within 15 seconds», «network error — <code>», «encoding <name> is not supported — UTF-8 is required», «non-text response (not UTF-8 or binary data)», «no extractable text (the page is empty or requires JavaScript)», «text extraction did not finish in time», «text extraction ran out of memory», «could not parse the HTML». The dependency is `parse5` 8.0.1 (MIT, the exact version is pinned in `packages/core/package.json`, one transitive dependency `entities`), it is imported only by the worker thread file `packages/core/src/url/html-worker.ts` and does not get into the app build. There is no link input in the app or in the MCP server. Downloading a public document is a network request from the owner's computer to that site, no models are called and nothing is paid. Check without cost (a local HTTP stand, the real `council` process through a test transport, scripted participants, 0 model calls; writes only to the new folder `.council-data/url-check-*` inside the repository): `COUNCIL_DEV=1 node packages/core/scenarios/url-materials/check.ts`.
- Preview and the prepared set: `council --preview-materials [--attach <path>]… [--include <path>]… [--no-ignore] [--url <address>]… [--materials-chars <n>]` prepares the materials, prints the same summary, then the exact text of the "Owner's materials" request section (full texts) and the folder listing, then `Prepared set: <id> (valid for 24 hours; no model calls were made)` and a hint line with the start command; the session is not created, the participants are not called, code 0. The topic and participants are not needed, any other start flag is rejected; at least one `--attach` or `--url` is needed. Full texts are printed only in this mode, the regular summary before the start does not print texts. `council --topic … --participant … --prepared-materials <id>` starts with exactly the shown set: without downloading and without re-reading files, the materials limit is taken from the set; the flag does not combine with `--attach`, `--url`, `--materials-chars` and `--preview-materials` (a reason and help, code 2, no network). The set lies in `prepared-materials/` of the same data folder for 24 hours (the app's preview mechanism), expired sets are not deleted automatically. An unfit set (`unknown`, `invalid`, `expired`, `corrupt`) gives `Prepared set not accepted: <reason>`, code 2.

```bash
COUNCIL_DEV=1 COUNCIL_HOME=.council-data npx council --url https://example.com/docs/page.html --preview-materials
COUNCIL_DEV=1 COUNCIL_HOME=.council-data npx council --topic "Что важно в документе" --prepared-materials <id> --participant scripted:packages/core/scenarios/consensus/p1.json --participant scripted:packages/core/scenarios/consensus/p2.json --max-rounds 3
```

These two commands reach the real site `example.com` (one network request, no models are called); the stand does not need the internet.
- Inside a folder there is no refusal: an environment file (`.env`, `.env.*`) and an item that could not be read are skipped with a reason in the "Skipped" summary, and the environment file is not opened.
- `--materials-chars <n>` — the limit of volume in text characters (UTF-16 units, like `--context-chars`); by default `defaults.materialsChars` from `config.json`, initially 60000. The limit applies to the initial set: explicitly named files over it reject the start, nothing is truncated (the message names the volume, the limit and the largest files), while a folder larger than the limit is not rejected — descriptions (`md`, `markdown`, `mdx`, `txt`, `rst`, `adoc`, `pdf`, `docx`, `docm`, `pptx`, `pptm`, `odt`, `odp`, `epub`, `rtf`, `doc`) closer to the root are taken from it while they fit, and without them the files closer to the root; the rest the participants read on request. A separate bound of the folder snapshot is 20000000 characters for all text files of attached folders; exceeding it rejects the start before the participants are called.
- Reading on request, as in the app: up to 5 names and 40000 characters per request, the folder listing up to 12000 characters (the limit also applies to collapsed lines: if the listing does not fit, deep folders collapse into smaller ancestors — a line per folder with the number of files and the size, and a cut at the last whole line happens only if even the lines of the attached folders do not fit; the number of files and the size stay in the header), no more than 3 participant calls per turn. If a participant read files, after the `Arguments:` line is printed `Read from the folder: <name> — <N> characters; <name> — <shown> of <N> characters` (the same in `council show <id>` and on `council resume`).
- `council resume` takes the saved snapshot; the source folder is not read after the start and may be changed or deleted.
- Relative paths are counted from the current folder.
- A path that contains a symbolic link is rejected whole. On macOS these are `/tmp` and `/var`: give the real path — `/private/tmp/…`.

## Formats and reasons

Accepted formats: text (UTF-8, UTF-16, Windows-1251), PDF including scans, DOCX/DOCM, XLSX/XLSM, PPTX/PPTM, ODT/ODS/ODP, EPUB, RTF, DOC, pictures through text recognition, ZIP as a folder.

The kind of a file is detected by content, not by extension, in this order: (1) text and PDF; (2) supported extraction: documents (DOCX/DOCM, XLSX/XLSM, PPTX/PPTM, ODT/ODS/ODP, EPUB), RTF and DOC, pictures; (3) Apple iWork, then ZIP as a folder; (4) the kind table below, by the start of the file; (5) the fallback: «encoding not recognized — UTF-8, UTF-16 with BOM or Windows-1251 is required» for text in an unsupported encoding, otherwise «binary file of an unknown format». The kind table is applied only to a file that did not become text and was not accepted by extraction, so a file accepted earlier is never rejected (text that starts with `ID3` or `MZ` stays text). An explicitly named file of another format rejects the start with `«path»: <reason>`; the same file inside a folder is skipped with the reason.

| Kind | Reason (en) | Reason (ru) |
|---|---|---|
| MP3, AAC, M4A, WAV, AIFF, FLAC, OGG/Opus | `<kind> audio — transcription is not performed` | `аудио <вид> — расшифровка не выполняется` |
| MP4/MOV, MKV/WebM, AVI | `video — the content is not passed on` | `видео — содержимое не передаётся` |
| RAR, 7z, tar, gzip, bzip2, xz, zstd | `<kind> archive — only ZIP is unpacked` | `архив <вид> — раскрывается только ZIP` |
| DMG | `DMG disk image — only ZIP is unpacked` | `образ диска DMG — раскрывается только ZIP` |
| Mach-O, ELF, PE, static library | `program — not a material` | `программа — не материал` |
| SQLite | `SQLite database — not supported` | `база SQLite — не поддерживается` |
| Fonts (TTF/OTF/TTC, WOFF/WOFF2) | `font — not a material` | `шрифт — не материал` |
| Excel 97 (XLS) | `Excel 97 spreadsheet — save it as XLSX` | `таблица Excel 97 — сохраните как XLSX` |
| PowerPoint 97 (PPT) | `PowerPoint 97 presentation — save it as PPTX` | `презентация PowerPoint 97 — сохраните как PPTX` |
| Apple iWork | `Apple iWork document (Pages, Numbers, Keynote) — export it to DOCX, XLSX, PPTX or PDF` | `документ Apple iWork (Pages, Numbers, Keynote) — экспортируйте в DOCX, XLSX, PPTX или PDF` |
| Unknown binary | `binary file of an unknown format` | `двоичный файл неизвестного формата` |
| Text in an unsupported encoding | `encoding not recognized — UTF-8, UTF-16 with BOM or Windows-1251 is required` | `кодировка не распознана — нужен UTF-8, UTF-16 с BOM или Windows-1251` |

Text without control bytes in an unrecognized encoding gets a kind reason only for a signature of 4 bytes or more (`RIFF`, `OggS`); a start of `ID3`, `MZ` or `BZh` keeps the encoding reason. A Compound File (CFB) or ZIP over 100 MiB gets the size reason of its format before any kind is detected.

Audio, video and the other kinds that are only named in a reason stay unsupported: nothing is transcribed or unpacked.
